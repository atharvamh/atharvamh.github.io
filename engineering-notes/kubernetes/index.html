Study Notes

Kubernetes

Notes on Kubernetes from first principles — starting from what a container actually is, and building up to the control loops, APIs, networks and storage that keep thousands of them running.

I

Containers & the Orchestration Problem

What a container really is underneath the tooling, and why running hundreds of them forces you into declarative state and reconciliation — namespaces, cgroups, layered images and OverlayFS, the OCI runtime stack, and the level-triggered control loop that every other part of Kubernetes is built on.

 II

The API Server & etcd

Every fact about the cluster is an object behind one API — the resource model, spec vs. status, labels and ownership, finalizers, etcd and Raft, resourceVersion and conflict handling, list-and-watch with informers, and the authentication-to-etcd request path.

 III

Control Plane & Node Architecture

The processes that make up a cluster and how they cooperate without ever calling each other — the API server, scheduler, controller managers, kubelet and kube-proxy, a full trace of one kubectl apply, what keeps running when each piece fails, and leader election on Leases.

 IV

Workloads & Scheduling

The Pod as the atomic unit and the controllers built on it — lifecycle, probes and graceful termination, Deployments and rollouts, StatefulSet identity, DaemonSets and Jobs — then how requests, limits, QoS, affinity, taints, priority and eviction decide where Pods run and who gives way.

 V

Networking

How every Pod gets a routable IP and how packets really move — veth pairs and bridges, routed vs. overlay networks, the CNI contract — then Services and EndpointSlices, kube-proxy’s iptables walk, cluster DNS, Ingress and Gateway API, and NetworkPolicy.

 VI

Storage, Config & Security

How data outlives containers and what each Pod is allowed to do — volumes, PersistentVolumes and claims, StorageClasses, the CSI lifecycle and snapshots, then ConfigMaps and Secrets, ServiceAccount tokens, RBAC, Pod Security and CEL admission policy.

 VII

Extending & Operating Kubernetes

Teaching Kubernetes new objects and behaviour with the same machinery its own controllers use — CRDs, controller-runtime, operators and admission webhooks — then running a real cluster: autoscaling, observability, upgrades and version skew, recovering from failure, and a hands-on capstone.
